## Findings

### AUD-01 · Vulnerable `vite` in the SPA toolchain · High · **Fixed**

- `npm audit` reported vite 7.3.6 under five advisories:
  - GHSA-9jrq-w75r-8gcw, cross-origin script execution through custom middleware;
  - GHSA-rq7h-c2jc-7f22, files served outside `server.fs.allow`;
  - three advisories in its `launch-editor` dependency, including command execution on Windows (GHSA-r825-w8mm-5pxw).
- **Exposure.** These affect the development server on a developer's machine. The published site is static output and was never exposed. The rule of the project is still no vulnerable libraries.
- **Fix.** vite 7.3.7, the first patched release, pinned exactly (`save-exact`). `npm audit` now reports 0 vulnerabilities, and the compiled site in `sitio-compilado/` was rebuilt with it.

### AUD-02 · Session keys stored unencrypted at rest · Medium · **Fixed**

- **Risk.** The Channel layer persists its Data Protection key ring in `DataProtection:KeysDirectory`, a volume, when there is more than one replica. Those keys encrypt the session cookie and the server-side ticket. Before, they were written in clear, and anyone able to read the volume or a backup of it could forge a session for any person. This was ASVS 1.6.2, tracked as SEC-01.
- **Fix:** [`KeyRingProtection`](../../src/channel/Modernization.ChannelApi/Auth/KeyRingProtection.cs).
  - The keys are encrypted with a certificate mounted from the secrets manager. Configure `DataProtection:CertificateFile`, as PFX (with `CertificatePasswordFile` if it has a password) or as PEM (with `CertificateKeyFile` if the key is a separate file).
  - `DataProtection:PreviousCertificateFiles` keeps older keys readable during a rotation.
  - **Outside Development, persisting the keys without a certificate stops the startup.** Error messages never include file paths.
  - [`deploy/k8s/channel-api.yaml`](../../deploy/k8s/channel-api.yaml) now sets `DataProtection__CertificateFile`.
- **Still for the platform team.** Encrypting the volume itself at rest.
- **Tests.** In `AuditHardeningTests`:
  - startup refused without a certificate;
  - key file contains no unencrypted key;
  - a second instance with the same certificate reads the session;
  - no path in errors.

### AUD-03 · Connector password could live in plain configuration · Medium · **Fixed**

- **Risk.** The new database connectors read their connection strings from configuration. A connection string with `Password=`/`PWD=` placed in `appsettings*.json` would end up in the repository or the image. Placed in an environment variable, it would end up in process dumps and in the orchestrator's console. Both are forbidden by the plan (section 7.2).
- **Fix.** [`ConnectorSecretGuard`](../../src/system/Modernization.SystemApi/ConnectorSecretGuard.cs). Outside Development, a connection string that carries a password and comes from any configuration source other than the secrets directory (`Secrets:Directory`, one key per file) stops the startup. The message names the key and the source, never the value. `PasswordFile` and `ConnectionStringFile` remain the alternatives.
- **Tests.** In `AuditHardeningTests`:
  - a password in memory or JSON configuration is refused outside Development;
  - the value is not echoed;
  - a password from the secrets directory, or none at all, is accepted.

### AUD-04 · PostgreSQL connections accepted `VerifyCA` · Low · **Fixed**

- **Risk.** `SSL Mode=VerifyCA` validates the certificate chain but not that the certificate belongs to the host. Any certificate from the same CA could impersonate the server.
- **Fix.** Only `VerifyFull` is accepted (`SecureConnectionFactory`), and the guide and ADR 0037 say so.
- **Test.** `PostgreSqlWithoutCertificateVerification_IsRefused` with `VerifyCA`.

### AUD-05 · Oracle connections could turn off the server name check · Low · **Fixed**

- **Risk.** A TCPS descriptor with `SSL_SERVER_DN_MATCH=no`, `false` or `off` keeps TLS but stops checking the server's name.
- **Fix.** Refused, spaces and case aside.
- **Test.** `OracleWithoutTcps_IsRefused` with both forms.

### AUD-11 · Vulnerable `@vitest/mocker` in the test runner · Low · **Fixed**

- GHSA-qxg6-89mg-rqv8 (code injection through unauthenticated manual mock registration) and GHSA-xp26-3454-mjgp (Windows backslash traversal of the redirect allowlist) were published on 2026-10-21 at about 19:50 UTC, after the audit, and both are moderate.
- They affect `@vitest/mocker` 5.0.0, which comes with vitest 5.0.0.
- OSV-Scanner in the `seguridad` workflow and `npm audit` in `ci` flagged them on the next push.
- **Exposure.** Vitest only runs the SPA unit tests on a developer machine or in CI, never in the published site.
- **Fix.** vitest 5.0.3, the first patched release, which brings `@vitest/mocker` 5.0.3. Pinned exactly; `npm audit` and an OSV query of every lock file report nothing.

### AUD-12 · Fake test passwords tripped the secret scanner · Informational · **Fixed**

- **What happened.** The connector tests in 674401e write invented passwords to temporary files, for example `s3cr3t-from-the-vault`. Gitleaks scans the whole history and its generic rule flags such values, which made the `seguridad` workflow fail from that commit on.
- **Fix.** The invented values (`from-the-vault`, `hunter2`, `never-leaves-the-server`) and a multi-part file name used in an upload test are added to the allowlist in `.gitleaks.toml`, with the reason next to each. No real secret was ever committed.

### AUD-06 · Container base images referenced by tag · Low · **Open**

- **Risk.** `deploy/docker/*.Dockerfile` use `node:24-alpine`, `mcr.microsoft.com/dotnet/sdk:10.0` and `mcr.microsoft.com/dotnet/aspnet:10.0-azurelinux3.0-distroless` by tag. A re-tagged image changes the build without a change in the repository.
- **Mitigation today.** The deployed images are referenced by digest and signature-verified at admission (`deploy/k8s`). Trivy scans the images in CI.
- **Recommendation.** Pin each `FROM` by digest and let a dependency bot propose updates. This belongs with H-17 (complete publication chain), which by decision of 2026-09-14 is in the last phase.

### AUD-07 · xUnit 2.x is marked legacy · Informational · **Accepted**

`dotnet list package --deprecated` reports `xunit 2.9.3` as legacy, with `xunit.v3` as the successor. It has no known vulnerability and only runs in tests. By the project's rule, packages are not updated without a vulnerability or a functional need.

### AUD-08 · Version ranges in `package.json` despite `save-exact` · Informational · **Accepted**

Several SPA dependencies keep `^` ranges from before `.npmrc` set `save-exact=true`. Builds use `npm ci` with the lock file, and the lock is what CI and the Dockerfile install, so the ranges have no effect on what is built. New dependencies are saved exactly, as vite now is.

### AUD-09 · The SPA's main bundle exceeds 500 kB · Informational · **Open**

The build warns that the main JavaScript chunk is larger than 500 kB after minification. It is a load-time cost, not a security issue. Splitting the rules and code screens with `import()` would reduce the first load.

### AUD-10 · `Modernization.Insights` keeps its name after the Insights screen was retired · Informational · **Accepted**

Since ADR 0035 the project holds the dashboard model and the end-of-life catalog. Renaming it would touch every reference for no behavioral change. The README and HANDOFF explain what it contains.

## Controls verified without findings

| Area | What was checked |
|---|---|
| Authentication | OIDC authorization code with PKCE, HTTPS metadata, issuer/audience/lifetime validation, `SaveTokens=false`, no inbound claim mapping. The development scheme cannot start outside Development (H-22) |
| Sessions | Server-side tickets (ADR 0011); cookie `__Host-`, `HttpOnly`, `Secure`, `SameSite=Strict`; idle and absolute lifetime; sign-out invalidates the ticket; step-up returns only to an allow-listed path |
| CSRF and CORS | Double-submit token on every mutation under `/api`, including the new pull and connection-test endpoints (tested). CORS is closed unless origins are listed, and then only `GET`/`POST` with two headers |
| Headers | CSP without `unsafe-inline`/`unsafe-eval` for the SPA and `default-src 'none'` for APIs, HSTS with preload, `nosniff`, `frame-ancestors 'none'`/`X-Frame-Options: DENY`, COOP/CORP, `no-store`, no server banner, no source maps. The compiled `index.html` has no inline script |
| Authorization between layers | The System layer only accepts scope and user headers from a caller authenticated with the service token, compared in constant time; the token has a minimum length. Every portfolio operation takes the scope as a parameter. Full scope is enforced again on uploads, mapping, connectors and pulls |
| Rate limiting | Per user after authentication (H-03). Uploads, pulls and connection tests share the upload policy with a sliding window |
| Input handling | 1 MB body limit except uploads. Labels, EAI codes, version ids, lever keys and targets are validated on both layers. The engine caps levers per scenario and the target range. Upload limits apply to files and database pulls alike |
| Files and XML | Client file names reduced to `Path.GetFileName`. Versions resolved from an enumerated list, never from input. Excel read with DTDs prohibited and explicit size limits (ADR 0034) |
| Regular expressions | All are source-generated with a match timeout; none without |
| Data access | No raw SQL anywhere. The connectors run deployment-defined statements, validated for shape, in read-only transactions that are always rolled back. A database's error message stays in the server log |
| Logging and audit | Security events with stable ids (`4001`–`4217`). Every logged value is neutralized (`SecurityAudit.Clean`) and users are pseudonymous subjects |
| Errors | RFC 7807 problem details without internals (H-10). The Channel layer forwards at most 500 characters of a System `detail` |
| Secrets | One key per file from the CSI driver. Development tokens carry a `dev-only` marker that refuses to start elsewhere. `AllowedHosts: *` refuses to start outside Development. No hard-coded secret found |
| Asynchrony and resources | No blocking waits on unfinished tasks. Broad `catch` blocks are filtered and logged. `HttpClient` comes from the factory, except in the load-test tool, which disposes it |
| Containers | Distroless runtime, non-root UID ≥ 10000 in Kubernetes, read-only root filesystem, all capabilities dropped, no service account token, diagnostics off |
| Network | Default-deny NetworkPolicies. The System layer only receives from the Channel layer and emits only DNS and mesh traffic. Each source database needs its own egress rule (documented) |
| CI | Actions pinned by SHA, `contents: read`, `persist-credentials: false`, locked restore, CodeQL, Trivy, Checkov and OSV-Scanner |
| SPA | No `dangerouslySetInnerHTML`, `eval` or `innerHTML`. External links use `rel="noopener noreferrer"`. No tokens in browser storage: only a dismissed-notice id and filter state. Install scripts disabled (`ignore-scripts`) |
| Dependencies | 0 vulnerable NuGet packages, direct or transitive, after pinning `System.Security.Cryptography.Pkcs` 10.0.13 for the new drivers (ADR 0037). 0 npm vulnerabilities after AUD-01 |
